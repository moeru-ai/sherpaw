# Compact speaker identification cases

Tests read nine fixed WAV files (about 2.25 MB), with no TTS generation or provider credentials. The browser runtime blocks non-local HTTP requests.

## Corpus

- Two enrolled synthetic voices: **alloy** and **nova**.
- Per voice: one Chinese and one English enrollment, plus distinct Chinese and English queries (eight TTS files total).
- One unregistered natural-speaker recording: the upstream `liudehua-test-sr-1.wav` file.

Two enrolled voices exercise discrimination and ranked candidates. Two languages preserve cross-language coverage, while two enrollment clips exercise aggregation. The independent natural recording checks rejection. Additional sample-count, editing, and lifecycle behaviors are covered by library/demo tests rather than more TTS files.

These are unchanged recordings from the original 2026-09-22 AIHubMix `tts-1` corpus: mono 16 kHz PCM16. `fixtures/manifest.json` preserves exact transcripts, source metadata, and SHA-256 checksums. Chinese text here is the actual spoken input, not documentation awaiting translation. Missing or changed files fail validation.

The earlier six-voice study remains in the [historical report](../../../../docs/research/speaker-identification-experiments.md). Its unknown-speaker failures still apply as evidence; the compact corpus is a regression fixture, not an equivalent accuracy benchmark. Removed files are not regenerated by any command in the normal test path.

## Run

Prepare the two published model packs at their pinned Hugging Face submodule revisions (requires Git LFS):

```sh
pnpm -F @sherpaw/speaker-identification test:prepare
```

```sh
pnpm -F @sherpaw/testing-audio test:speakers
pnpm -F @sherpaw/testing-audio ablate:speakers
```

Tests read the local `install/bin/wasm/preload.data` from each model submodule; the data bytes are identical to the original ONNX models. Browser requests remain local.

The six regression cases comprise one file matrix and two Chinese fake-microphone cases per model. File matrices include all four held-out TTS queries and the natural unknown. The browser harness lives in `packages/sandbox/tests/speaker-identification`, alongside the sandbox app. Capture follows `getUserMedia -> AudioWorklet -> recorder -> Worker -> WASM`, with a fresh browser per microphone case.

The explicit ablation command compares Chinese-only and bilingual enrollment, query duration/amplitude, and leave-one-voice-out behavior. It writes English Markdown/JSON reports under `docs/research`; JSON references the fixture manifest instead of embedding its transcripts again. Threshold sweeps reuse the same scores and are not calibration results.

## Maintaining fixtures

`packages/testing-audio/scripts/generate-speaker-fixtures.mjs` is an explicit authoring tool. It follows only the entries in the current manifest, skips existing files, and requires `AIHUBMIX_API_KEY` only to generate a missing file. It cannot silently restore the removed six-voice corpus. Regenerated audio can differ: review the recording and update its hash deliberately. Tests, CI, model preparation, and the demo never invoke this script.

```sh
node packages/testing-audio/scripts/generate-speaker-fixtures.mjs --env-file /path/to/.env.local
```
